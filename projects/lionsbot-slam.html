Introduction

Autonomous cleaning robots need to navigate complex indoor environments like malls, airports, and warehouses — often spanning 50,000+ square meters with dynamic obstacles and changing layouts.

Traditional 2D Lidar SLAM struggled in these environments due to drift accumulation over large distances and inability to handle "corridor environments" (low geometric features). My mission was to architect a tightly-coupled Lidar-Inertial Odometry (LIO) system using factor-graph optimization to maintain centimeter-level consistency across global coordinates.

The Challenge

Large-scale environments present unique challenges for localization systems:

"When your robot operates for 8+ hours across 50,000 sqm, even small drift errors compound into meters of localization error."

Key technical challenges included:

  • Geometric degeneracy in featureless long corridors
  • Dynamic noise filtering (people, warehouse equipment)
  • Lidar beam distortion correction from high-speed motion
  • Resource-constrained optimization (GTSAM iSAM2) on embedded ARM
  • Large-scale pose-graph management for 100k+ sqm maps

The Solution

I designed and implemented a multi-sensor fusion SLAM system combining 3D Lidar, wheel odometry, and IMU data through a factor graph optimization framework.

Key innovations included:

  • Factor-Graph Optimization using GTSAM for multi-sensor global consistency
  • Geometric Degeneracy Detection to prevent drift in symmetrical corridors
  • Descriptor-based Place Recognition for robust loop closure candidates
  • Voxel-based Downsampling for real-time PCL processing overhead reduction

Tech Stack

System Architecture

Technical Deep Dive

The core of our system is a tightly-coupled Lidar-Inertial Odometry (LIO) pipeline that fuses high-frequency IMU measurements with 3D Lidar scans using a factor graph formulation. This approach allows us to model the probabilistic relationships between sensor measurements and robot states, enabling globally consistent trajectory estimation.

1. Factor Graph Formulation

We model the SLAM problem as a Maximum a Posteriori (MAP) estimation over a factor graph. The state vector X = {x₀, x₁, ..., xₙ} contains robot poses at each keyframe. Factors encode constraints from odometry, IMU pre-integration, and loop closures. 

// GTSAM Factor Graph Construction
#include <gtsam/nonlinear/ISAM2.h>
#include <gtsam/slam/BetweenFactor.h>
#include <gtsam/navigation/ImuFactor.h>

gtsam::NonlinearFactorGraph graph;
gtsam::Values initialEstimate;

// Add IMU pre-integration factor between consecutive poses
auto imuFactor = gtsam::ImuFactor(
    X(i), V(i),      // Previous pose and velocity
    X(i+1), V(i+1),  // Current pose and velocity
    B(i),            // IMU bias
    preintegrated    // Pre-integrated IMU measurements
);
graph.add(imuFactor);

// Add Lidar odometry factor from scan matching
gtsam::Pose3 relativePose = performScanMatching(prevCloud, currCloud);
auto lidarFactor = gtsam::BetweenFactor<gtsam::Pose3>(
    X(i), X(i+1), relativePose, lidarNoise
);
graph.add(lidarFactor);

2. Geometric Degeneracy Detection

A critical challenge in large-scale environments is geometric degeneracy — when the environment lacks sufficient geometric features to constrain all 6-DoF of the robot's pose. This commonly occurs in long, featureless corridors where the translational component along the corridor axis becomes unobservable from Lidar alone.

We detect degeneracy by analyzing the eigenvalues of the Hessian matrix from the scan-matching optimization. If any eigenvalue falls below a threshold, we increase reliance on IMU and wheel odometry for that axis: 

// Degeneracy Detection via Hessian Eigenvalue Analysis
Eigen::SelfAdjointEigenSolver<Eigen::Matrix6d> solver(hessian);
Eigen::Vector6d eigenvalues = solver.eigenvalues();

const double DEGENERACY_THRESHOLD = 100.0;
for (int i = 0; i < 6; ++i) {
    if (eigenvalues(i) < DEGENERACY_THRESHOLD) {
        // Axis 'i' is degenerate - reduce Lidar weight for this DOF
        lidarNoise(i, i) *= 10.0;  // Inflate covariance
        ROS_WARN("Degeneracy detected on axis %d, inflating covariance", i);
    }
}

// Compensate with IMU/Wheel Odometry
if (isDegenerateState) {
    graph.add(gtsam::BetweenFactor<gtsam::Pose3>(
        X(i), X(i+1), wheelOdomPose, wheelOdomNoise  // Tighter noise
    ));
}

3. Loop Closure with Scan Context

For place recognition, we use Scan Context descriptors — a rotation-invariant representation of the 3D point cloud. When revisiting a location, we detect loop closure candidates by comparing descriptors and validate them with ICP-based geometric verification. 

// Loop Closure Detection with Scan Context
ScanContext sc;
auto descriptor = sc.makeDescriptor(currentCloud);

// Query KD-tree for nearest neighbors in descriptor space
auto [loopIdx, distance] = scManager.detectLoopClosure(descriptor);

if (distance < LOOP_THRESHOLD) {
    // Geometric verification with ICP
    pcl::IterativeClosestPoint<PointT, PointT> icp;
    icp.setInputSource(currentCloud);
    icp.setInputTarget(keyframeDatabase[loopIdx].cloud);
    
    pcl::PointCloud<PointT> aligned;
    icp.align(aligned);
    
    if (icp.getFitnessScore() < ICP_FITNESS_THRESHOLD) {
        // Add loop closure factor to graph
        gtsam::Pose3 loopPose(icp.getFinalTransformation());
        graph.add(gtsam::BetweenFactor<gtsam::Pose3>(
            X(loopIdx), X(currentIdx), loopPose, loopNoise
        ));
    }
}

4. Incremental Optimization with iSAM2

To maintain real-time performance on embedded ARM hardware, we use iSAM2 (Incremental Smoothing and Mapping) for incremental graph optimization. Unlike batch solvers that re-optimize the entire graph, iSAM2 only updates the affected portion when new factors are added, achieving O(log n) complexity for most updates. 

// Incremental Optimization with iSAM2
gtsam::ISAM2Params params;
params.relinearizeThreshold = 0.1;
params.relinearizeSkip = 1;
gtsam::ISAM2 isam(params);

// Called at each new keyframe
void updateGraph(const gtsam::NonlinearFactorGraph& newFactors,
                 const gtsam::Values& newValues) {
    isam.update(newFactors, newValues);
    
    // Retrieve optimized estimates
    gtsam::Values result = isam.calculateEstimate();
    currentPose = result.at<gtsam::Pose3>(X(latestIdx));
    
    // Update global map with corrected trajectory
    updateGlobalMap(result);
}

Key Insight: The combination of degeneracy-aware sensor fusion and incremental optimization allows our system to maintain <5cm localization accuracy even in 100,000+ sqm facilities with long featureless corridors — a scenario where traditional Lidar-only SLAM would accumulate meters of drift.

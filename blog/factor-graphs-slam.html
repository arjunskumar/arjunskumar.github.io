Factor Graphs for SLAM: A Practical Introduction

SLAM 8 min read • January 2026

Factor graphs have become the de facto standard for formulating and solving SLAM problems. This article explains why they're so powerful and how to use them effectively with libraries like GTSAM.

Why Factor Graphs?

Traditional approaches to SLAM treated it as a filtering problem — maintaining a belief over the current state and updating it with new measurements. While elegant, this approach has a fundamental limitation: once information is marginalized out, it's lost forever.

Factor graphs take a different approach. Instead of maintaining a single belief, we keep track of all the constraints (factors) between all the states (variables). This enables:

  • Loop closure correction: When we revisit a location, we can propagate the correction backward through the entire trajectory
  • Incremental optimization: With algorithms like iSAM2, we can efficiently update only the affected parts of the graph
  • Multi-sensor fusion: Different sensors simply add different types of factors to the same graph

The Mathematical Foundation

A factor graph represents a factorization of a probability distribution. For SLAM, we model the joint probability of all robot poses and landmarks:

\[P(X | Z) \propto \prod_{i} \phi_i(X_i)\]

Each factor \(\phi_i\) encodes a constraint — it could be an odometry measurement, a landmark observation, or a loop closure detection.

Implementing with GTSAM

GTSAM (Georgia Tech Smoothing and Mapping) is the most widely used factor graph library in robotics. Here's a minimal example: 

#include <gtsam/nonlinear/NonlinearFactorGraph.h>
#include <gtsam/slam/BetweenFactor.h>
#include <gtsam/nonlinear/LevenbergMarquardtOptimizer.h>

// Create the factor graph
gtsam::NonlinearFactorGraph graph;
gtsam::Values initial;

// Add a prior on the first pose
auto priorNoise = gtsam::noiseModel::Diagonal::Sigmas(
    gtsam::Vector3(0.1, 0.1, 0.01));
graph.addPrior(1, gtsam::Pose2(0, 0, 0), priorNoise);

// Add odometry factors between poses
auto odomNoise = gtsam::noiseModel::Diagonal::Sigmas(
    gtsam::Vector3(0.2, 0.2, 0.05));
graph.emplace_shared<gtsam::BetweenFactor<gtsam::Pose2>>(
    1, 2, gtsam::Pose2(1.0, 0, 0), odomNoise);

// Optimize
gtsam::LevenbergMarquardtOptimizer optimizer(graph, initial);
gtsam::Values result = optimizer.optimize();

Key Takeaways

Factor graphs transform SLAM from a filtering problem into an optimization problem, enabling globally consistent solutions even with delayed loop closures.

In production systems, the choice of noise models, outlier rejection strategies, and incremental solvers like iSAM2 become critical. I'll cover these topics in future notes.

Modern C++17 Patterns for Robotics

C++ 12 min read • January 2026

C++17 introduced features that dramatically improve code safety and expressiveness. Here's how I use them in production robotics systems.

1. std::optional for Sensor Data

Sensor readings can fail. Before C++17, we'd use sentinel values (-1, nullptr) or output parameters. std::optional makes failure explicit: 

// Before: Unclear what -1 means
double getLidarRange(int beam_id); 

// After: Explicit optionality
std::optional<double> getLidarRange(int beam_id) {
    if (!isBeamValid(beam_id)) {
        return std::nullopt;
    }
    return ranges_[beam_id];
}

// Usage
if (auto range = getLidarRange(42); range) {
    processPoint(*range);
} else {
    handleMissingScan();
}

2. Structured Bindings for Transforms

Robotics is full of pairs and tuples — transforms, covariances, timestamped data. Structured bindings make decomposition clean: 

// Decomposing a transform
auto [translation, rotation] = getOdometry();

// With maps
std::map<std::string, Sensor> sensors;
for (const auto& [name, sensor] : sensors) {
    LOG_INFO("Sensor {} online: {}", name, sensor.isHealthy());
}

// Multiple return values
auto [success, pose, covariance] = localize(scan);
if (success) {
    publishPose(pose, covariance);
}

3. if constexpr for Compile-Time Branching

When writing templated code for different sensor types, if constexpr eliminates dead branches at compile time: 

template<typename SensorT>
void processMeasurement(const SensorT& sensor) {
    if constexpr (std::is_same_v<SensorT, LidarSensor>) {
        // This code only compiles for Lidar
        auto pointcloud = sensor.getPointCloud();
        slamBackend_.addScan(pointcloud);
    } else if constexpr (std::is_same_v<SensorT, CameraSensor>) {
        // This code only compiles for Camera
        auto image = sensor.getImage();
        visualOdometry_.processFrame(image);
    }
}

4. std::string_view for Zero-Copy Logging

In real-time systems, unnecessary allocations hurt. std::string_view provides a non-owning view: 

// No allocation - just a pointer and length
void logMessage(std::string_view msg, std::string_view level = "INFO") {
    std::cout << "[" << level << "] " << msg << "\n";
}

// Works with string literals, std::string, char arrays
logMessage("Robot initialized");                    // No copy
logMessage(sensor.getName());                       // No copy
logMessage(std::string("Dynamic: ") + value);       // Temporary ok

5. [[nodiscard]] for Critical Returns

Prevent silent failures by forcing callers to handle return values: 

[[nodiscard]] bool armMotors() {
    if (!safetySystemOk()) return false;
    motors_.enable();
    return true;
}

// Compiler warning if ignored!
armMotors();  // Warning: ignoring return value

// Correct usage
if (!armMotors()) {
    emergencyStop();
}
Modern C++ isn't about using every new feature — it's about choosing the ones that make your intent clearer and your bugs louder.

Compiler Flags I Use

# Enable C++17 with strict warnings
-std=c++17 -Wall -Wextra -Wpedantic -Werror
# Catch more issues
-Wshadow -Wnon-virtual-dtor -Wold-style-cast
# Sanitizers for development
-fsanitize=address,undefined
